## Local archive and D3D12 follow-up

I repeated the offline sweep on the same two XCL revisions, with the RTX 5080, driver and DXIL validator listed above. The stock CLI used split Wave64, seed 1, one worker, a 2,000-program sample and no size cap. Both revisions emitted 205/205 compute programs in the per-instruction route. The per-lane results were:

| Offline per-lane sweep | Direct parent | PR 2203 |
| --- | ---: | ---: |
| Compute programs emitted | 26/205 | 39/205 |
| Whole-wave branch refusals | 35 | 2 |

The 16 KiB-capped sweep covered 120 compute inputs and emitted 26 on the parent and 39 on the PR. A separate probe linked against the exact XCL libraries validated all 26 parent outputs and all 39 PR outputs with DXIL 1.9.2609.5. The PR retained all 26 parent successes. All **13 newly emitted Wave64 programs** created D3D12 compute pipelines on the RTX 5080.

The three shaders already discussed in the PR moved from branch refusals to two `IMAGE_SAMPLE_LZ` refusals and one `IMAGE_LOAD` refusal. I also compared seven locally matched compute programs previously investigated in the NVIDIA fork. Six moved from a whole-wave branch refusal to SDWA half conversion, LDS atomics or a buffer atomic. One stayed at `IMAGE_STORE`. Per-lane emission remained 0/7 on both XCL revisions. The per-instruction backend validated and built **7/7 D3D12 compute pipelines** on both revisions.

The last verified stage for these inputs was offline pipeline creation. Runtime shader output and gameplay performance remain unverified for this comparison.
