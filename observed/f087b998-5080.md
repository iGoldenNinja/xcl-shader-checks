# XCL sampler and split-Wave64 checks on RTX 5080

I tested clean XCL main `f087b998d0d51a9f11bbfa0761967a63e778edd9` and the sampler merge's first parent `c55ba167295333c81b7024a307e654ec818c475f`. Hardware was an RTX 5080 16 GB, driver 617.14, Windows 11 Pro 25H2 build 26200.9974, Ryzen 9 5900X and 32 GB RAM. The release builds used Rust 1.98.1 and DXC/DXIL 1.9.2609.5. [Sampler PR 1117](https://github.com/xcl-dev/xcl/pull/1117)

I applied only PR 1117's sampler fixture changes to the parent checkout. The aniso-point pixel readback failed there at pixel (0,0), returning **6.904297** for an expected **26**. On the clean merge commit the same fixture passed all 256 pixel checks. The ordinary implicit-LOD sampling control and the S# decoder test also passed.

On the same clean main build, both PR 2203 split-Wave64 GPU fixtures passed again. This covers whole-wave branch output for 64- and 128-thread groups and readback for live and dead SCC. Hardware was selected with `XCL_ADAPTER=5080`, and the GPU fixtures ran without skips. [PR 2203](https://github.com/xcl-dev/xcl/pull/2203)

The last verified stage was synthetic D3D12 rendering and compute readback. Title rendering and frame pacing on this revision remain unmeasured.
